# PYS

一个运行在 Windows 终端里的 C++ 小游戏 demo:启动先进入 ASCII 大字标题页,按 Enter 开始,在 512 x 512 的地图上移动、采集资源,并购买自动机器人代为采集;状态栏随终端窗口大小调整布局,方向键可以切到商店场景。

仅作学习性质的 demo,用 Windows 控制台 API 直接绘制,无第三方依赖。

## 运行

需要 Windows + PowerShell + MinGW g++。

```powershell
pwsh build.ps1    #递归收集 src 下所有 .cpp 一起编译,产物 .\PYS.exe
./PYS.exe
```

`build.ps1` 自己扫源文件,加新 `.cpp` 不用改脚本、也不用改 `.vscode/tasks.json`(默认构建任务是 `build PYS (all sources)`)。

拆分后**不要再单独编译某个文件**,那样链接不到其它编译单元的符号;旧任务 `C/C++:g++.exe build active file` 已从 `tasks.json` 移除。

## 命令行

```powershell
.\PYS.exe --seed 12345                #复现同一张初始地图
.\PYS.exe --size 1024x512             #地图尺寸,默认 512x512
$env:PYS_SEED = "12345"; .\PYS.exe    #双击运行时没有命令行参数,走环境变量
.\PYS.exe --help
```

调试面板(`owoishere`)会显示当前 `seed:`;把那个数填回 `--seed` 就能重开同一张图。尺寸或种子填错不会让程序崩:非法值会打印一行说明并回退,尺寸被 `World::init` 拒绝时回退默认规模。提示文字用英文,因为宿主终端常是 GBK/936,中文提示可能显示成乱码。

## 目录结构

```
src/
  main.cpp            组装与主循环:键盘分发、界面选择、背包与商店这些会话状态
  platform/           只碰 Windows 控制台 API 的部分
    console_ctrl.*    退出标志与 Ctrl+C / Ctrl+Break 回调
  game/
    types.h           商品条目、机器人、矿脉等类型定义
    world.h/.cpp      被模拟的世界:矿脉网格与储量池、覆盖率、机器人推进
  content/
    title_assets.*    标题页的字模、字母排布、色板与变色节奏
tests/
  world_test.cpp      直接链接 src/game/world.cpp 的行为测试
build.ps1             收集 src 下所有 .cpp 编译出 PYS.exe
run_tests.ps1         编译并运行 tests/
```

程序使用当前终端的可见区域绘制,支持运行时调整窗口大小和字体大小,不再强制设置窗口尺寸。运行时隐藏光标,退出时恢复。

## 测试

```powershell
pwsh run_tests.ps1
```

`tests/` 下的用例直接链接 `src/game/world.cpp`,不开终端也不画屏幕,验证矿脉生成与探测、储量池扣减、机器人迈步与撞墙折返、同种子可复现铺图这些规则。

判据: `src/game/` 里不该出现任何 Windows API(`windows.h`、`CHAR_INFO`、`VK_*`、`GetTickCount64`)。一旦出现,就说明有逻辑漏在那一层里,变成没法测试的代码。

## 操作

| 按键 | 作用 |
| --- | --- |
| `W` / `A` / `S` / `D` | 移动 `@` |
| `E` / `空格` | 从脚下矿脉的储量池里取货,一次 1~3#(未探明的矿脉采不到) |
| `V` | 探测:揭示以 `@` 为中心 3x3 范围内首次碰到的矿脉,一次点亮整条 |
| `→` | 切到商店场景 |
| `←` | 切回游戏场景 |
| `W` / `S` / `↑` / `↓` | 商店场景:上下移动光标选择商品 |
| `Enter` | 标题页:开始游戏;商店场景:买下光标指向的商品 |
| `owoishere` | 输入这串字母开启调试模式,再输入一遍关闭 |
| `F` / `T` / `Y` | 调试模式:加 10000# / 矿脉覆盖率 +1% / 矿脉覆盖率 -1% |
| `Q` / `Ctrl+C` | 清除游戏画面并退出 |

## 已实现

- 在内存中维护控制台画面,字符变化时记录待绘区域,每帧最多调用一次 `WriteConsoleOutputA` 提交变化区域;画面不变时不调用输出 API。
- 仅在游戏状态或可见窗口变化时合成画面,比较最终画面后提交变化区域;静止时不重复生成文字或输出。
- 非阻塞读取当前终端的键盘事件,长按使用系统按键重复;失焦不触发退出,其他窗口按键不会控制游戏。
- 采集键同时接受 `E` 和空格(`VK_SPACE`),两者走同一段逻辑:只在游戏场景且画面尺寸足够时生效;一次从脚下矿脉的池里取 1~3#,受余量约束不会取成负数,未探明的矿脉踩在上面也采不到。
- 游戏期间关闭输入回显、行输入和快速编辑,持续消费输入队列,避免游戏按键残留到 PowerShell;正常退出时恢复输入模式和光标。
- Q、Ctrl+C 和 Ctrl+Break 共用主线程退出清理:清除当前可见画面、光标回到可见区域左上角,再恢复终端状态,保留滚动历史。
- 矿以"矿脉"为单位存在:从随机种子格长出一簇连续格子(32~128 格),整条脉共用一个储量池,总量 = 面积 x 100#。格子只记录"我属于哪条脉",不存独立储量;矿脉列表只追加、不删除,所以格子里的 id 永远有效。
- 地图默认覆盖率 8%,第一条脉固定从地图中心起长——玩家出生点就在中心,否则在 512x512 上开局可能要走很久才碰到第一块矿。
- 矿脉默认未被探测,画出来和空地一样,也采不到;按 `V` 探测脚下 3x3,命中即点亮整条脉(格子只存归属,所以一次翻转就看见全貌,不需要 flood fill)。
- 矿不可再生:原先"剩余量见底就补一波"的逻辑已删除。采空即整条脉从网格撤走,不留废矿痕迹。地图右侧的 `Remaining` 因此是"全图还剩多少 #",不再是格子数。
- 终端宽度达到 80 列时使用右侧状态栏,较窄时使用底部状态栏;文字按可用宽度裁剪,不会换行覆盖地图。
- 场景状态机:`scene` 为 2 时是标题页(开局就停在这里),为 0 时是采集场景,为 1 时是商店场景。
- 标题页的 `CONSOLE` 由 5x4 像素字模拼成,每个字母分两趟画:先在与本体同色相但不提高亮度的前提下、右下各偏一格画稀疏的 `.`,再盖上密实发亮的 `#`。控制台没有 alpha 通道,立体感靠字符密度和亮度双重拉开;颜色相位按字母错开,整串字横向流动变色。窗口不足 46 列时退化成一行带空格的普通字。
- 场景切换在内存中清空并重绘,随后一次提交;回到游戏场景时恢复现有资源,长按方向键不会重复重绘。
- 地图默认 512 x 512,尺寸已经是运行期参数而非编译期常量(为"世界规模可选"预留);显示不全时由视口跟随玩家滚动,调整终端大小不改变资源分布、玩家坐标和已采集数。
- 窗口小于 32 列或 12 行时提示放大窗口并暂停采集,仍可按 Q 退出;放大后继续游戏。
- 绘制坐标包含终端可见区域的起始偏移,窗口变化导致输出被裁剪时会在下一帧重试。
- 商店由一张商品表驱动:光标选择、价格扣费、数量上限和列表行都由表生成,加一个商品只需多填一行。
- `Auto Robot` 可以购买,每只占地图一行,地图行数(默认 512)排满即锁死;`Bot Speedup` 分五档,速度依次 1.00/0.75/0.50/0.25/0.10 秒一格,价格依次 1000/2000/4000/8000#。买满的商品价格位显示 `MAX`,不再扣钱。
- 机器人自己走动采集:先走到下一格,再看那格所在脉的池里还有没有矿;吃到显示咬合的 `=`,没吃到按行进方向显示 `<` 或 `>`,撞墙折返。每步从池里取 1#,和玩家手采用同一个池子、记同一笔账。
- 相同尺寸、覆盖率、种子及随机分布实现可重建相同的初始矿脉分布,调试面板会显示种子。调高覆盖率后重铺是在同一序列上放宽门槛,低覆盖率的结果是高覆盖率结果的子集。
- 种子只决定初始矿脉,不能单独还原游戏进度:存档还要保存采集造成的池余量变化、矿脉是否已探明、随机引擎当前状态以及玩家和机器人状态。本项目尚未实现存档。
- 右侧栏标出正在运作的东西(机器人数/上限、当前速度档、脚下矿脉的余量与探测结果),调试模式开启时再追加覆盖率数值和可用键位。
- 调试模式:敲 `owoishere` 开关,九字母滑窗匹配,中间打错不必整串重打。`F` 发 10000#(只进背包,不改地图),`T`/`Y` 调覆盖率并立刻重新生成全部矿脉;开局生成和重铺共用同一份实现。

## 尚未完成

- 商品表还留着两个空位,暂时没有第四、第五种商品可买;商店只有买入,没有卖出或退款。
- 机器人不做寻路,只在各自那一行左右直走,与玩家重叠时不显示;买满 32 只之后只能继续投速度升级。
- 自动采集没有单独统计,机器人采到的和玩家采的混在同一个 `Collected` 里,分不出各自贡献。
- 底部状态栏(终端宽度不足 80 列时)不显示机器人数、速度档和调试状态,所以在窄终端里即使开了调试也没有任何提示;调试短语本身也要求窗口够大才会被识别。
- 标题页只在启动时出现,游戏里没有按键能退回去,想再看一次只能重启程序。
- 矿机、缓存与物流都还没有:自动采集仍是"一行一只"的机器人,没有放置、没有缓冲停机、也没有取货动作。已确定的设计是矿机占地 3x2、缓存 30#、满了就停直到被取走,运输打算走无人机方案;这些实现尚未开始。
- 资源种类仍是单一的一种 `#`:物品、配方、机器数量的外部数据表还没接进来。

## 已知问题

- 依赖 `windows.h`,只能在 Windows 上编译运行。
- 在采集场景输入 `owoishere` 会顺带触发 `W`/`S` 的移动和两处 `E` 采集,因为同一个按键既进短语缓冲又被游戏逻辑消费;在商店场景输入则没有副作用。
- 调试模式的 `T`/`Y` 会重新生成全部矿脉:当前分布、已探明状态和已开采的余量一并作废,机器人位置与已购数量保留。
