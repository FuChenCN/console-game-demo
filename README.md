# PYS

一个运行在 Windows 终端里的 C++ 小游戏 demo:启动先进入 ASCII 大字标题页,按 Enter 开始,在 512 x 512 的地图上移动、采集成团的矿脉,购买矿机放到矿池上自动挖矿。矿格按所属矿池上色,每个未采空的池每 5 分钟回 1 格。状态栏随终端窗口大小调整布局,非标题页时方向键可以切到商店场景。

仅作学习性质的 demo,用 Windows 控制台 API 直接绘制,无第三方依赖。

## 运行

需要 Windows 10 及以上、PowerShell,以及支持 C++17 的 MinGW-w64 g++(脚本直接调 `g++`,不依赖 CMake 等其它构建工具)。

```powershell
pwsh build.ps1    #递归收集 src 下所有 .cpp 一起编译,产物 .\PYS.exe
./PYS.exe
```

`build.ps1` 自己扫源文件,加新 `.cpp` 不用改脚本、也不用改 `.vscode/tasks.json`(默认构建任务是 `build PYS (all sources)`)。

拆分后**不要再单独编译某个文件**,那样链接不到其它编译单元的符号;旧任务 `C/C++:g++.exe build active file` 已从 `tasks.json` 移除。

## 目录结构

```
src/
  main.cpp            组装与主循环:键盘分发、界面选择、背包、商店与矿机放置
  platform/           只碰 Windows 控制台 API 的部分
    console_ctrl.*    退出标志与 Ctrl+C / Ctrl+Break 回调
  game/
    types.h           商店商品条目
    world.h/.cpp      被模拟的世界:矿脉生成、矿池储量与重生、矿机取矿
  content/
    title_assets.*    标题页的字模、字母排布、色板与变色节奏
tests/
  world_test.cpp      直接链接 src/game/world.cpp 的行为测试
build.ps1             收集 src 下所有 .cpp 编译出 PYS.exe
run_tests.ps1         编译并运行 tests/
```

程序使用当前终端的可见区域绘制,支持运行时调整窗口大小和字体大小,不再强制设置窗口尺寸。运行时隐藏光标,退出时恢复。

## 测试

```powershell
pwsh run_tests.ps1
```

`tests/` 下的用例直接链接 `src/game/world.cpp`,不开终端也不画屏幕,验证:矿脉从种子可复现、提高密度时旧格子仍被保留、矿池 id 与网格/剩余量三方对账、采集同步扣池、每池 5 分钟回 1 格、100% 密度铺满、矿机放置与取最近格、矿机空转与回填续挖、非法尺寸不污染状态。

判据: `src/game/` 里不该出现任何 Windows API(`windows.h`、`CHAR_INFO`、`VK_*`、`GetTickCount64`)。一旦出现,就说明有逻辑漏在那一层里,变成没法测试的代码。

## 操作

| 按键 | 作用 |
| --- | --- |
| `W` / `A` / `S` / `D` | 采集场景:移动 `@`(长按一次走多格,按系统的按键重复速率) |
| `E` / `空格` | 采集脚下的资源(该位置的 `#` 消失,计数 +1) |
| `Enter` | 标题页:开始游戏;商店:买下光标项;采集场景:在脚下有矿的格子放置矿机 |
| `→` / `←` | 非标题页时切到商店 / 切回采集场景 |
| `W` / `S` / `↑` / `↓` | 商店场景:上下移动光标选择商品(到顶/到底循环) |
| `owoishere` | 输入这串字母开启调试模式,再输入一遍关闭(窗口至少 32 × 12 才会被识别) |
| `F` / `T` / `Y` | 调试模式:加 10000# / 资源密度 +1% / 资源密度 -1% |
| `Q` / `Ctrl+C` / `Ctrl+Break` | 清除游戏画面并退出(任何场景、任何窗口尺寸) |

## 已实现

- 在内存中维护控制台画面,字符变化时记录待绘区域,每帧最多调用一次 `WriteConsoleOutputA` 提交变化区域;画面不变时不调用输出 API。
- 仅在游戏状态或可见窗口变化时合成画面,比较最终画面后提交变化区域;字符和颜色都比对,静止时不重复输出。
- 非阻塞读取当前终端的键盘事件,长按使用系统按键重复;失焦不触发退出,其他窗口按键不会控制游戏。移动键会把 `wRepeatCount` 一次用掉,采集键不重复计数。
- 采集键同时接受 `E` 和空格(`VK_SPACE`),两者走同一段逻辑:只在游戏场景且画面尺寸足够时生效,同一格拾取后即刻置空,重复按键不会二次计数。
- 游戏期间关闭输入回显、行输入和快速编辑,持续消费输入队列,避免游戏按键残留到 PowerShell;正常退出时恢复输入模式和光标。
- Q、Ctrl+C 和 Ctrl+Break 共用主线程退出清理:清除当前可见画面、光标回到可见区域左上角,再恢复终端状态,保留滚动历史。
- 矿脉按团块生成:从种子出一批候选中心,按密度激活前 N 条,再用随机游走长成 30–159 格的连通块。512 x 512、6% 时约 170 个池、15.7k 格。
- `cells` 存的是矿池 id(1..N,0 为空),同一片矿脉同 id;池的足迹单独记一份,重生只按足迹回填,不再全图扫描。
- 密度仍是"有矿格数 / 总格数":提高密度时旧格子原样保留(候选前缀性质),100% 时把剩余空格并给相邻池,仍然铺满整张图。
- 相同尺寸、密度、种子可重建完全相同的矿脉和池 id;调试面板显示种子。调高密度后重铺沿用同一序列,低密度矿格是高密度结果的子集。
- 每个未满的矿池每 300 秒回 1 格(池级节奏,不是全图共享);回填按足迹找第一格空的,回到容量为止,不溢出、不追补。调试面板显示池数与回填节奏。
- 矿格按所属矿池 id 上色,7 种前景色循环;玩家 `@` 用高亮白,矿机 `&` 用高亮黄,空格保持终端默认色。
- `Mining Rig` 可以购买(100#,不限量);在采集场景站在 `#` 上按 Enter 放置:地基那格矿被采掉并计入背包,矿机占住这一格。
- 矿机每隔当前速度档取走所属池里离自己最近的一格矿,直接进背包;和玩家亲手采的记同一笔账。池子采空后矿机空转,等回填出一格再继续。
- `Rig Speedup` 分五档,速度依次 1.00/0.75/0.50/0.25/0.10 秒一格,价格依次 1000/2000/4000/8000#;买满显示 `MAX`,不再扣钱。
- 矿池和矿机只在采集场景运转:切到商店或窗口太小时冻结,回来从原位置继续。重铺地图会拆掉矿机(已购数量保留,可以免费重放)。
- 终端宽度达到 80 列时使用右侧状态栏,较窄时使用底部状态栏;文字按可用宽度裁剪,不会换行覆盖地图。
- 场景状态机:`scene` 为 2 时是标题页(开局就停在这里),为 0 时是采集场景,为 1 时是商店场景。
- 标题页的 `CONSOLE` 由 5x4 像素字模拼成,每个字母分两趟画:先在与本体同色相但不提高亮度的前提下、右下各偏一格画稀疏的 `.`,再盖上密实发亮的 `#`。窗口不足 46 列时退化成一行带空格的普通字。
- 场景切换在内存中清空并重绘,随后一次提交;回到游戏场景时矿脉和矿机都保持原样。
- 地图默认 512 x 512,尺寸是运行期参数;显示不全时由视口跟随玩家滚动,调整终端大小不改变矿脉分布、玩家坐标和已采集数。
- 窗口小于 32 列或 12 行时提示放大窗口并暂停采集、商店操作、矿机与标题动画,仍可按方向键切场景、按 Q 退出;放大后继续游戏。
- 绘制坐标包含终端可见区域的起始偏移,窗口变化导致输出被裁剪时会在下一帧重试。
- 商店由一张商品表驱动:光标选择、价格扣费、数量上限和列表行都由表生成;矿机不限量,升级锁五档。
- 调试模式:敲 `owoishere` 开关,九字母滑窗匹配,中间打错不必整串重打;采集、商店、标题页都能敲(标题页里按下也只会翻转开关,不画任何提示)。`F` 发 10000#,`T`/`Y` 调密度并立刻重铺整张地图。

## 尚未完成

- 商品表还留着两个空位,暂时没有第三、第四种商品可买;商店只有买入,没有卖出或退款。
- 矿机不会移动、不做寻路,只挖自己脚下那片池;池子空了就干等回填,不会转去别的池。
- 自动采集没有单独统计,矿机挖到的和玩家亲手采的混在同一个 `Collected` 里,分不出各自贡献。
- 底部状态栏(终端宽度不足 80 列时)不显示矿机数、速度档和调试状态,所以在窄终端里即使开了调试也没有任何提示;调试短语本身只在窗口至少 32 列 × 12 行时才会被识别。
- 标题页只在启动时出现,游戏里没有按键能退回去,想再看一次只能重启程序。
- 存档还没做:需要保存矿池 id/足迹/剩余量、回填计时、矿机位置与已购数量,以及随机引擎状态。

## 已知问题

- 依赖 `windows.h`,只能在 Windows 上编译运行。
- 回填速度远低于开采速度:一个池 5 分钟才回 1 格,而一台顶层矿机 0.1 秒就取一格。512 x 512 / 6% 的 170 个池合计约 34 格/分钟,单台 0 档矿机就有 60 格/分钟,池子会先被挖空。数值如需调整,改 `ORE_REGROW_MS`。
- 调试模式的 `T`/`Y` 会重铺整张地图:矿池 id 全部重排,已放置的矿机被拆掉(已购数量保留),当前资源分布和回填进度作废。调试工具,正常流程用不到。
- 右侧栏没有高度提示:宽度够了但高度只有 12–14 行时,`Running:` 之后的矿机/速度行落在可见区域外;开调试时完整面板要 22 行(基础信息 15 行),更矮的终端会把池信息、种子和键位提示裁掉。
- 放置矿机时如果脚下正好是矿,那格矿会被直接收走并计入 `Collected`;矿机站在玩家同一格时被 `@` 盖住,要走开才看得到 `&`。
- 在采集场景输入 `owoishere` 会顺带触发 `W`/`S` 的移动和两处 `E` 采集;在商店场景输入会把光标上下各挪一格(净位置不变),并触发一次重绘。
- 矿机可以叠在同一片池上(放在不同格子),没有"每池一台"的限制;池越富,叠矿机收益越高。
- 矿池回填只在采集场景推进:待在商店里的时间不计入 5 分钟节奏,回到采集场景后每个未满的池最多补 1 格。
- `#` 的颜色按池 id 每 7 个循环一次,离得远的两个池可能同色,只能靠形状区分。
