# PYS

一个运行在 Windows 终端里的 C++ 小游戏 demo:启动先进入 ASCII 大字标题页,按 Enter 开始,在 512 x 512 的地图上移动、采集铁/铜/锡三类矿脉,按 → 打开背包并在右侧制作矿机,再回到地图上把矿机放到矿池里自动挖矿。

每个矿格有 100 个数据,要采 100 次才消失;矿格在屏幕上占两列,直接显示 `Fe`、`Cu`、`Sn`。每个未采空的池每 5 分钟补 1 个满格(100 数据)。商店已移除,所有成品都从背包右侧的制作面板产出。

## 运行

需要 Windows 10 及以上、PowerShell,以及支持 C++17 的 MinGW-w64 g++(脚本直接调 `g++`,不依赖 CMake 等其它构建工具)。

```powershell
pwsh build.ps1    #递归收集 src 下所有 .cpp 一起编译,产物 .\PYS.exe
./PYS.exe
```

`build.ps1` 自己扫源文件,加新 `.cpp` 不用改脚本、也不用改 `.vscode/tasks.json`(默认构建任务是 `build PYS (all sources)`)。编译用 `-static` 链接,产物自带 libstdc++/libgcc/libwinpthread,不依赖 MinGW 的 DLL 或 PATH。

拆分后**不要再单独编译某个文件**,那样链接不到其它编译单元的符号;旧任务 `C/C++:g++.exe build active file` 已从 `tasks.json` 移除。

## 目录结构

```
src/
  main.cpp            组装与主循环:键盘分发、场景切换、背包/制作、矿机放置
  platform/           只碰 Windows 控制台 API 的部分
    console_ctrl.*    退出标志与 Ctrl+C / Ctrl+Break 回调
  game/
    world.h/.cpp      被模拟的世界:矿脉生成、矿池储量与重生、矿机取矿、按矿种产出
  content/
    title_assets.*    标题页的字模、字母排布、色板与变色节奏
tests/
  world_test.cpp      直接链接 src/game/world.cpp 的行为测试
build.ps1             收集 src 下所有 .cpp 编译出 PYS.exe
run_tests.ps1         编译并运行 tests/
```

程序使用当前终端的可见区域绘制,支持运行时调整窗口大小和字体大小,不再强制设置窗口尺寸。运行时隐藏光标,退出时恢复。

## 测试

```powershell
pwsh run_tests.ps1
```

`tests/` 下的用例直接链接 `src/game/world.cpp`,不开终端也不画屏幕,验证:矿脉从种子可复现、提高密度时旧格子仍被保留、矿池 id 与网格/数据量三方对账、每格 100 次采集才消失、采集/矿机同步扣池、每池 5 分钟补 1 个满格、100% 密度铺满、矿机放置(不结算资源)与取最近格、矿机空转与回填续挖、三类矿的前缀稳定、每格矿种可查、矿机产出按矿种分开、非法尺寸不污染状态。

判据: `src/game/` 里不该出现任何 Windows API(`windows.h`、`CHAR_INFO`、`VK_*`、`GetTickCount64`)。一旦出现,就说明有逻辑漏在那一层里,变成没法测试的代码。

## 操作

| 按键 | 作用 |
| --- | --- |
| `W` / `A` / `S` / `D` | 采集场景:移动 `@`(长按一次走多格,按系统的按键重复速率) |
| `E` / `空格` | 采集脚下 1 个数据(每格 100,挖空该格才消失,按矿种入包) |
| `Enter` | 标题页:开始游戏;采集场景:在脚下有矿的格子放置矿机;背包:制作光标指向的配方 |
| `→` | 采集场景:打开背包(背包里再按无效果) |
| `←` | 背包或采集场景:切回采集场景 |
| `W` / `S` / `↑` / `↓` | 背包场景:上下移动制作光标(到顶/到底循环) |
| `owoishere` | 输入这串字母开启调试模式,再输入一遍关闭(窗口至少 32 × 12 才会被识别) |
| `F` / `T` / `Y` | 调试模式:铁/铜/锡各 +10000 / 资源密度 +1% / 资源密度 -1% |
| `Q` / `Ctrl+C` / `Ctrl+Break` | 清除游戏画面并退出(任何场景、任何窗口尺寸) |

## 已实现

- 在内存中维护控制台画面,字符变化时记录待绘区域,每帧最多调用一次 `WriteConsoleOutputA` 提交变化区域;画面不变时不调用输出 API。
- 仅在游戏状态或可见窗口变化时合成画面,比较最终画面后提交变化区域;字符和颜色都比对,静止时不重复输出。
- 非阻塞读取当前终端的键盘事件,长按使用系统按键重复;失焦不触发退出,其他窗口按键不会控制游戏。
- 采集键同时接受 `E` 和空格(`VK_SPACE`),每按一次扣该格 1 个数据,数据归零才消失,重复按键不会二次计数。
- 游戏期间关闭输入回显、行输入和快速编辑,持续消费输入队列;正常退出时恢复输入模式和光标,清除可见画面但保留滚动历史。
- 矿脉按团块生成:从种子出一批候选中心,按密度激活前 N 条,再用随机游走长成 30–159 格的连通块。512 x 512、6% 时约 170 个池、15.7k 格、157 万数据。
- `cells` 存矿池 id(1..N,0 为空),`oreLeft` 存每格还剩多少数据(1..100);同一片矿脉同 id,池的足迹单独记一份,重生只按足迹回填,不再全图扫描。
- 密度仍是"有矿格数 / 总格数":提高密度时旧格子原样保留(候选前缀性质),100% 时把剩余空格并给相邻池,仍然铺满整张图。
- 相同尺寸、密度、种子可重建完全相同的矿脉和池 id;调试面板显示种子。调高密度后重铺沿用同一序列,低密度矿格是高密度结果的子集。
- 每个未满的矿池每 300 秒补 1 个满格(新格直接带 100 数据);回填按足迹找第一格空的,回到容量为止,不溢出、不追补;只挖掉部分数据的格子不补,必须整格挖空才有空格可回。
- 矿脉分三类:铁(Fe)、铜(Cu)、锡(Sn)。每个池从头到尾只有一种类型,按池 id 均分,默认图约各占三分之一。
- 每格在屏幕上占 2 列,直接写元素符号 `Fe`/`Cu`/`Sn`,相邻矿格连成一片字符堆;铁浅灰、铜橙、锡青灰,挖过但没挖空时换成同色系暗色。玩家 `@` 高亮白,矿机 `&` 高亮品红。
- 因为一格占两列,横向可见的地图格数只有终端列数的一半(80 列 + 侧栏时约 24 格宽);`View` 和视口滚动都以格为单位。
- 背包场景左栏是库存(铁/铜/锡/总量、已放/已造矿机、速度档),右栏是制作面板:W/S 选配方,Enter 制作,扣对应矿种;制作失败会提示 `Not enough ore` 或 `maxed out`。
- 配方一:`Mining Rig`,60 Fe + 30 Cu + 10 Sn,不限量。配方二:`Rig Speedup`,200 Fe + 100 Cu + 100 Sn,每做一档三样成本翻倍,共五档(1.00/0.75/0.50/0.25/0.10 秒),做满显示 `MAX`。
- 玩家采集按矿种入包;矿机每次出手也从所属池的矿种计入对应库存。背包里的余额就是制作材料,不再有单独的 `Collected` 总账。
- 在采集场景站在矿格上按 Enter 放置矿机:只占这一格,不动用脚下数据,落地后从脚下开始挖;放置不扣料也不结算资源,成本已经由制作时的材料支付。
- 矿机每隔当前速度档从所属池里离自己最近的一格扣 1 个数据,格子挖空才消失;池子采空后矿机空转,等回填出一个满格再继续。
- 矿池和矿机只在采集场景运转:切到背包或窗口太小时冻结,回来从原位置继续。重铺地图会拆掉矿机(已造数量保留,可以免费重放)。
- 终端宽度达到 80 列时使用右侧状态栏,较窄时使用底部状态栏;文字按可用宽度裁剪,不会换行覆盖地图。
- 场景状态机:`scene` 为 2 时是标题页,为 0 时是采集场景,为 1 时是背包+制作。
- 标题页的 `CONSOLE` 由 5x4 像素字模拼成,分阴影/本体两趟画;窗口不足 46 列时退化成一行带空格的普通字。
- 地图默认 512 x 512,尺寸是运行期参数;显示不全时由视口跟随玩家滚动,调整终端大小不改变矿脉分布、玩家坐标和库存。
- 窗口小于 32 列或 12 行时提示放大窗口并暂停采集、制作、矿机与标题动画,仍可按方向键切场景、按 Q 退出。
- 调试模式:敲 `owoishere` 开关,九字母滑窗匹配;采集、背包、标题页都能敲。`F` 给三类矿各加 10000,`T`/`Y` 调密度并立刻重铺;调试面板显示池数、Fe/Cu/Sn 池数、回填节奏和 `cell:100#`。

## 尚未完成

- 制作面板只有两个配方;没有拆解、出售或退款,做错只能继续用。
- 矿机不会移动、不做寻路,只挖自己脚下那片池;池子空了就干等回填。
- 自动采集没有按"玩家/矿机"分开统计,只按矿种入库。
- 底部状态栏(终端宽度不足 80 列时)不显示矿机数、速度档和调试状态。
- 标题页只在启动时出现,游戏里没有按键能退回去。
- 存档还没做:需要保存矿池 id/足迹/剩余量、每格 `oreLeft`、回填计时、矿机位置、三类库存、已造矿机与速度档,以及随机引擎状态。

## 已知问题

- 依赖 `windows.h`,只能在 Windows 上编译运行。
- 回填和开采的节奏需要自己调:一个池 5 分钟才补 100 数据,170 个池合计约 3,400 数据/分钟;单台矿机 0 档 60/分钟、满档 600/分钟。数值要改就改 `ORE_REGROW_MS` 和 `ORE_PER_CELL`。
- 调试模式的 `T`/`Y` 会重铺整张地图:矿池 id 全部重排,已放置的矿机被拆掉(已造数量保留),当前资源分布和回填进度作废。
- 右侧栏没有高度提示:宽度够了但高度只有 12–14 行时,`Running:` 之后的矿机/速度行落在可见区域外;开调试时完整面板要 22 行(基础信息 15 行)。
- 放置矿机不结算资源;矿机站在矿格上时 `&` 会盖住脚下的 `Fe/Cu/Sn`,但数据仍在池里,从下一步开始扣。矿机与玩家同格时被 `@` 盖住。
- 在采集场景输入 `owoishere` 会顺带触发 W/S 移动和两处 E 采集;在背包场景输入会让制作光标上下各挪一格(净位置不变)。
- 矿机可以叠在同一片池上(放在不同格子),没有"每池一台"的限制。
- 矿池回填只在采集场景推进:待在背包里的时间不计入 5 分钟节奏,回来每个未满的池最多补 1 个满格。
- 三类矿的数据量相同、制作时按矿种分别扣料;还没有冶炼、分仓上限或按矿种定价。
- 一格两列让横向视野减半;窗口刚好 80 列时地图只有约 24 格宽,想要更大视野需要拉宽终端或缩小字体。
